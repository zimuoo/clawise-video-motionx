# Clawise 动效导演

先确认内容，再选择表现方式。目标是让观看者理解一个具体信息，并愿意继续看下去。

## 开始之前

从用户提供的上下文、工程、网站和素材中确定：

- 产品或主题是什么；观看后最应记住的一句话。
- 使用渠道、比例、时长、是否静音观看、是否需要循环。
- 可用的真实材料：logo、界面截图、录屏、数据、照片、音频。事实与数字记录来源；原创示意图标明性质。
- 品牌：实际配色、字体、用词与已有视觉资产。客户品牌优先于模板默认值。

缺少普通偏好时直接给出合理方案并说明假设。只有缺失事实、必需素材或用户明确要求比较时才停下来讨论。不要为每一步机械请求确认。

## 选择视觉语言

| 解释任务 | 可以使用 |
|---|---|
| 展示一个操作及结果 | keynote-ui、ui-space、真实录屏 |
| 解释关系、过程、因果 | SVG/Canvas 系统图、whiteboard |
| 数学与趋势 | math-explainer、finance-chart；使用可核验数据 |
| 概念和世界观 | flat-science、原创 SVG 插画 |
| 强调语句与口播词 | kinetic-type、talking-head |
| 展示一个物件或空间关系 | object-3d；先验证单个镜头 |
| 产品短片与自定义结构 | blank、clawise-launch |

语言与材质可组合。不要把所有内容都做成居中的标题卡，也不要为追求复杂度替换真实素材。

## 分镜与节奏

先写 3–5 个关键帧，每个包含：画面信息、主体、动作、镜头、读完需要的时间。设计一个开场变化，一个清楚的主要解释段落，一个有停留的结束画面。

变化应有原因：引导注意、展示状态、解释因果、比较前后。镜头与对象分别控制。需要快节奏时改变镜头尺度、信息密度和动作间隔；需要平静时用少量持续运动与阅读停留。

不要用固定 BPM、切镜次数或一组历史平均数判定所有视频的质量。设计要服从当前内容与用户要求。

## 实现与评审

先建立最难的一帧或一个镜头。通过 `still` 查看实际结果，再扩展时间轴。保持素材本地化，变量可编辑，任意 seek 可重现。

`check` 验证工程和布局；`qa` 提供视频运动与闪帧的启发式提示。它们不能替代画面、试听和内容判断。阅读停留、片尾、静音 loop、慢速品牌片都有合理的静止时段，按分镜判断而非盲目消除。

需要更多表现词汇时按需阅读 [library/README.md](library/README.md) 和 [craft.md](craft.md)，不要一次加载全部库。
