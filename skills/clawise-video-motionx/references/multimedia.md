# 图片、声音与视频协作

MotionX 编排本地素材并导出可编辑短片。生成能力由 Clawise 当前会话中的工具和已安装技能提供；此包不携带其密钥、模型、私有 helper 或服务配置。

## 选择实际能力

| 需求 | 优先执行 |
|---|---|
| 背景、插画、关键帧、参考图修改 | Clawise 图片插件提供的 `image_generate`；读取当前工具 schema |
| 普通口播 | 用户录音；需要合成时用 `clawise_tts_list_voices`、`clawise_tts_synthesize` |
| 文生视频、图生视频、数字人、山谦克隆音色、山谦混剪 | 实际安装的 `shanqian-ai` 技能及其对应参考 |
| 配乐和动作音效 | MotionX 本地 `sound`，或用户提供的音频 |
| 镜头编排、标题、字幕、动画、预览和导出 | MotionX；已有 Remotion 工程沿用 `clawise-remotion-video` |

尊重用户指定的能力和现有素材。生成图片适合视觉创作；产品 UI、logo、统计数字和客户案例仍用真实资料，不能生成虚构截图冒充产品证据。

先检查当前工具列表、技能目录与是否启用。技能路径使用 Clawise 实际提供的位置；也可能在当前 agent 的 workspace/skills 中，不硬编码用户目录。只读运行所需的技能文档，不读取密钥或连接配置。已配置的能力无需为本次视频重新配置。

## Clawise 图片插件

1. 使用会话实际暴露的 `image_generate` 工具；`clawise-openai-image` 是插件/图片供应能力的标识，不是可调用工具名。不要假设存在 `clawise_image_generate`，也不要调用仅在其他宿主存在的生图工具。
2. 读取当前工具参数，沿用 Clawise 已选择的模型与供应配置；不要在工程里固化模型、URL、API key 或重写服务请求。若用户指定模型但当前不可用，明确说明。
3. 把分镜、画幅、主体、景别、色彩、光线和文字留白写成提示词。多镜头复用同一主体设定；改图或图生图时按当前工具支持传入真实参考图。品牌文字、标题、字幕优先在 MotionX 排版，避免烘焙到图片里。
4. 工具若只返回“后台任务已启动”或任务 id，表示尚未生成完成。按工具提供的完成通知/任务查询方式等待；等待需有界并报告进展，不重复提交生图任务。没有查询工具时等待宿主完成事件，不编造轮询 API。
5. 取得成功结果后，提取其中的已交付本地文件。只有临时 URL 时，使用宿主提供的保存方式取得文件；不把网页、URL、任务 id 或 base64 字符串传给 `asset`。失败、取消或超时应报告原任务状态，保留已成功的素材。
6. 先看实际图片，再归档；核对构图、主体一致性、裁切和文字留白。输出多图时按场景逐张选择与导入。

```sh
motionx asset ./film --file "/actual/completed/background.png" --id intro-background --source clawise-image
```

## 山谦配合

读取安装的 `shanqian-ai/SKILL.md`；图像、视频、混剪分别按其引用读取对应参考和决策说明。通过该技能自己的 helper 完成正常创作，不复制 helper、不新建客户端、不探查服务内部实现。按用户已给的要求执行；只有缺少会影响执行的选择或该能力明确要求且尚未取得的确认，才使用当前宿主的提问工具。已给出的选择和授权继续有效，不因切换技能重复询问。

- **图生视频：** 先等图片插件成功，取得实际图片文件，再交给山谦作为图生视频输入。描述动作与镜头，保持原主体。确认山谦产出的真实视频后再导入，不能用 MotionX 的平移缩放冒充完成了图生视频。
- **数字人：** 选定可用人像，先生成/导入配音，把实际人像和音频交给山谦；山谦支持的克隆音色流程按其技能执行。不能假设有名为 `shanqian_tts` 的工具或通用独立 TTS 动作。
- **混剪：** 若由山谦成片，将本次选中的真实图片、视频传给其本地素材流程。若只需要几个素材镜头，取回素材后由 MotionX 编排；不要同时运行两套完整成片流程。
- **结果交接：** 等待成功终态，优先使用 helper 交付的 `CLAWISE_MEDIA` 本地文件，逐个验证；不使用尚未交付的临时存储路径。图片、视频均可用下方命令导入；不能把含逗号的多路径输出整体当作单个文件。
- **失败与补参：** 缺参数时按山谦技能处理补参；失败时告诉任务提交者原因及可公开的任务编号，不把失败输出或内部连接信息写入工程。只保留本次实际素材来源和路径，不分发山谦服务协议与配置。

```sh
motionx asset ./film --file "/actual/delivered/shot.mp4" --id opening-shot --source shanqian-ai
```

## 素材归档和片内接入

`asset` 要求本地非空媒体文件、可用的 FFmpeg/ffprobe，以及唯一 `--id`。先检查元数据并完整解码校验，再写入清单；校验限时 120 秒，适合短片素材。支持 PNG/JPEG/WebP/GIF/AVIF、MP4/MOV/WebM/MKV、WAV/MP3/M4A/AAC/OGG/FLAC/Opus。SVG 等已有代码素材仍按工程正常资源管理。

命令复制至 `assets/generated/<id>-<hash>.<ext>`，打印 JSON；其中 `path` 为相对路径，包含类型、来源、SHA-256、字节数、真实尺寸或时长。`assets/media.json` 记录这些信息，不写入机器绝对路径或凭据。同一素材重复导入不会增加条目；同一 id 的不同版本会拒绝覆盖，请用新 id。

同一工程按顺序导入。另一个导入正在写入时会明确拒绝，等待后重试；进程中断留下锁文件时，先确认没有导入进程，再移除 `assets/.media-import.lock`。不会自动覆盖其他导入的清单。

`asset` 不自动修改 `index.html`、不生成字幕、不混音。把返回路径接入源文件；下例路径中的 HASH 必须替换为命令实际返回值，不能直接照抄：

```html
<img data-mx-id="intro-background" src="assets/generated/intro-background-HASH.png" alt="" />
<video data-mx-id="opening-shot" src="assets/generated/opening-shot-HASH.mp4"
  data-start="0" data-media-start="0" data-duration="3" muted playsinline></video>
```

`data-start` 是片内开始时间，`data-media-start` 是素材裁入点，`data-duration` 是使用时长，单位均为秒。不得超过素材剩余时长。需要剪辑外的重复播放时先明确设计循环。默认将生成视频原声静音；要保留时再显式加入并检查混音，避免与口播重叠。

普通配音按 [voice.md](voice.md) 导入并建立词轴。已固定 12 秒等片长时，不用 `--fit` 擅自改片长；依据实际配音调整文案、停顿或取得用户对片长变化的授权。配乐应低于口播，数字人的内嵌语音与单独旁白不能双重播放。

完成后逐场景看 still、运行 check 和真实 render，检查生成镜头、字幕、音轨与固定时长。交付工程、`assets/media.json` 和成片；复制工程到另一目录也应能预览。用户只要成片时，不强制附加素材清单说明。

## 能力不可用

- 图片工具未暴露/未配置：报告具体缺项；可继续文字分镜和现有素材的工程工作。不得自建云客户端或静默改用别的供应商。
- 山谦技能缺失、禁用或应用无法完成任务：说明该镜头受阻，不自动安装、启用或替用户切换成其他能力。用户允许时可用已有视频或纯代码动效替代，并如实标注。
- TTS 不可用：保留脚本与字幕草稿，可用用户录音继续；草稿时间不是实际语音对齐结果。不要声称已完成有声成片。
- 已有足够信息时直接继续。所有后续 generation 仍遵守用户实际授权范围，不能把“配置好了”视为无限批量生成的许可。
